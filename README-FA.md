# شروع نسخه آنلاین روبی شاپ

این پروژه یک نمونه اولیه واقعی برای انتقال روبی شاپ از فایل HTML محلی به برنامه آنلاین است. پنل با گوشی هم قابل استفاده است، اما برای آنلاین شدن باید یک‌بار سرویس‌های میزبانی و دیتابیس تنظیم شوند.

## امکانات موجود
- صفحه معرفی ساده فارسی و راست‌چین
- صفحه ورود مدیر با ایمیل و رمز عبور Supabase
- پنل واکنش‌گرا برای افزودن، دیدن و حذف محصولات
- ذخیره محصولات در دیتابیس آنلاین PostgreSQL در Supabase
- کنترل دسترسی پایه: فقط کاربر واردشده می‌تواند محصولات را مدیریت کند

## هنوز ساخته نشده
سفارش و پرداخت آنلاین، آپلود و مدیریت فایل عکس، رنگ و سایزهای متنوع، تخفیف، مشتریان، وبلاگ، ویرایشگر دیداری Drag & Drop، انتقال خودکار اطلاعات فایل v26. این‌ها باید مرحله‌به‌مرحله اضافه شوند.

## مراحل راه‌اندازی (از طریق مرورگر گوشی)

### ۱) ساخت دیتابیس
1. وارد سایت Supabase شوید و یک پروژه جدید بسازید.
2. رمز دیتابیس را در جای امن نگه دارید.
3. از منوی SQL Editor، گزینه New query را بزنید.
4. محتوای فایل `supabase/schema.sql` را کامل کپی کنید، اجرا (Run) را بزنید.
5. از بخش Authentication / Users یک کاربر مدیر با ایمیل و رمز قوی بسازید. سپس شناسه UUID همان کاربر را کپی کنید و در SQL Editor این دستور را با شناسه واقعی اجرا کنید:
   `insert into public.admin_users (user_id) values ('UUID-کاربر-مدیر');`
   به‌جای `UUID-کاربر-مدیر` شناسه واقعی کاربر را قرار دهید. بدون این مرحله، حتی مدیر هم اجازه مدیریت محصولات ندارد.
6. آدرس و کلید عمومی پروژه در فایل `.env.local` تنظیم شده‌اند. کلید عمومی (Publishable) قابل استفاده در مرورگر است؛ کلید Secret یا service_role را هرگز در سایت قرار ندهید.

### ۲) انتشار برنامه
این سورس باید در یک مخزن GitHub قرار بگیرد و به Vercel متصل شود. در تنظیمات پروژه Vercel این دو Environment Variable را بسازید:
- `NEXT_PUBLIC_SUPABASE_URL` = آدرس پروژه Supabase
- `NEXT_PUBLIC_SUPABASE_ANON_KEY` = کلید anon/public پروژه
سپس Deploy را اجرا کنید.

### ۳) اجرای محلی برای توسعه
نیازمند Node.js نسخه 20 یا جدیدتر:
```bash
npm install
cp .env.example .env.local
npm run dev
```

## نکته امنیتی مهم
کلید `service_role` را هرگز در برنامه مرورگر یا متغیرهایی با پیشوند `NEXT_PUBLIC_` قرار ندهید. فقط کلید anon/public استفاده شود. سیاست‌های RLS در این نسخه پایه‌اند؛ قبل از فروش واقعی باید نقش مدیر محدودتر و سیاست‌های دسترسی دقیق‌تر شوند.

## پیشنهاد مسیر توسعه
1. تکمیل ورود مدیر و نقش مدیر واقعی
2. آپلود عکس محصولات در Storage
3. رنگ، سایز، موجودی و قیمت متغیر
4. سفارش‌ها و وضعیت سفارش
5. صفحات و دسته‌بندی‌ها و وبلاگ
6. قالب عمومی فروشگاه و پرداخت
7. ابزار انتقال محصولات و محتوای نسخه HTML قبلی
